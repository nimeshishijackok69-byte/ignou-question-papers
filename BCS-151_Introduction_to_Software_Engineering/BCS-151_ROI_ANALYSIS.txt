             little preparation it needs. No speculation - only what was asked.

================================================================================
TOPIC 1: SRS - SOFTWARE REQUIREMENTS SPECIFICATION  (10/10 papers, ~205 marks)
ROI 10/10 - The single biggest topic of the exam. 40-50% of Q1 every time.
================================================================================
SUBTOPICS:
1.1 IEEE SRS format - its sections and how to fill each one
    [D21:20, J24:25, D23:25, J23:25, D22:25, J22:15, J21:15, J25:15, D25:20, J26:20]
    -> asked in EVERY paper, always attached to a case study
1.2 Characteristics of a good SRS (correct, complete, unambiguous, verifiable...)
    - theory component inside SRS answers
1.3 Functional requirements vs Non-functional requirements
    - write 4-5 of each for the given system in every SRS answer
1.4 Writing the SRS itself for the case-study system
    - ALWAYS "Make necessary assumptions" -> announce assumptions in 2-3 lines
1.5 Need / importance of SRS
    [D21 1(a) preface]
1.6 Users of SRS document
    - standard theory; pair it with 1.5

GUARANTEED RECURRING ANSWER TEMPLATE (memorize once):
   IEEE SRS = Introduction (purpose, scope, definitions, references, overview)
   + Overall description (product perspective, functions, users, constraints)
   + Specific requirements (functional, non-functional: performance, security,
   usability, reliability) + assumptions & dependencies.
   Practice ONE full SRS (e.g., Online Examination System), then swap the
   system-specific lines for any other case study.

TOPIC 2: DATA FLOW DIAGRAMS  (10/10 papers, 100 marks - exactly 10 every time)
ROI 10/10 - zero-variation question. Never missed, never changed shape.
================================================================================
SUBTOPICS:
2.1 What is a DFD - definition and purpose
    [J26:10, D25:10 - both opened the question with "What is a DFD?"]
2.2 Components of DFD and their notations
    - Process (circle/rounded rectangle), Data flow (arrow),
      Data store (open rectangle), External entity (square)
    [J26:10, D25:10, J25:10]
2.3 Level-0 / Context diagram (whole system = one process with external entities)
    [J21:10, D21:10, J22:10, D22:10, J23:10, D23:10, J24:10, J25:10, D25:10, J26:10]
2.4 Level-1 DFD (break main process into 3-6 subprocesses)
    [same papers as 2.3 - the question is always "first two levels" or
     "zero and first level"]
2.5 Level-2 DFD (explode one subprocess of level-1)
    - required by "first two levels of DFD" wording [J21, J25, J26]
2.6 Notations/conventions used to draw DFDs
    [J25:10 - "Briefly discuss the various notations" + draw]
2.7 Rules: balancing of flows between levels, no control logic, data stores
    only touched by processes
2.8 RELATED: Data Dictionary - contents and example for one data element
    [D21 short note 5, D23 1(c):5, J24 3(b):10]
    -> treat as a sub-branch of DFD; asked 3 times, cheap to learn

STRATEGY: The case study is always announced in Q1. You draw DFD levels for
the SAME system. One practiced example = one guaranteed 10 marks.

5. PRIORITY ORDER - WHAT TO STUDY, IN WHAT ORDER
--------------------------------------------------------------------------------
TIER 1 (do first - appears in 10/10 papers, ~65+ marks combined):
    1. SRS IEEE template + one practiced case-study SRS
    2. DFD: notation, context level, level-1, level-2 (one worked example)
    3. GANTT + PERT for one case-study task list
    4. SDLC: Waterfall + Spiral full; 2 lines each for Prototype/RAD/Iterative

TIER 2 (do second - ~35-40 marks):
    5. Testing family map + black vs white box + test case + principles
    6. Use-case diagram symbols + one template diagram
    7. Static objects + object/class + utility objects (theory pages)
    8. ERD for one case study

TIER 3 (quick wins - ~30 marks, all memorization):
    9. CMM five levels (fixed answer)
    10. Maintenance: need + 4 types (verbatim-repeated question)
    11. SCM activities (returned D25)
    12. Coupling/cohesion definitions + lists

TIER 4 (one-night reads):
    13. SQA/error-fault-failure/cost of quality
    14. Debugging strategies
    15. Metrics (hot after J26)
    16. Data dictionary, StepWise, SPM tasks

BARE-MINIMUM PASS MATH (target ~40 of 100 for 75% weightage pass):
    Q1: SRS (15-25) + model (5-10) + use case/ERD (5-10) + short theory (5)
        -> Tier 1+2 alone secures ~30-40 of the compulsory 40 marks
    Plus any two comfortable 10-mark questions from Tier 2/3 -> 50+ total.
    With Tier 1 fully prepared you cannot score below 50-55; Tier 3 pushes
    you into 70+ territory.
