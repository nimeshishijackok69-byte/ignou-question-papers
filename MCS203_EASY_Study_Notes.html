1. What Linux is, and its architecture 10 MARKS

Exam asks: "With the help of a diagram, explain the fundamental architecture of Linux" / "Explain Linux architecture with special focus on the kernel and its components."
🧠 In simple words — the restaurant idea
Think of a restaurant. Customers sit in the dining area and order food. They are not allowed into the kitchen — they cannot touch the stove or the fridge. They give their order to a waiter, and the waiter carries it to the kitchen. The kitchen staff do the real work: cooking, storing, cleaning, and packing.
  • Dining area = user space — your apps (browser, editor, games).
  • Waiter = system call — the only legal way to ask for a service.
  • Kitchen = kernel — the privileged part that actually controls the CPU, memory, disk and network.
Why keep them separate? So a badly behaved customer (a buggy app) cannot burn down the kitchen. If one app crashes, the whole computer does not die.
📝 Definition to write in the exam
Linux is a free, open-source operating system with a monolithic kernel. "Monolithic" means the main services — process management, memory management, file system, device drivers, networking and IPC — all live inside one privileged kernel program and talk to each other directly. Extra drivers can be added while the system is running using Loadable Kernel Modules (LKMs).
🖼️ Diagram to draw (copy this)
USER SPACE — apps: browser, editor, shell, games ┌────────────────────────────────────────────┐ │ Applications System libraries │ └───────────────┬────────────────────────────┘ │ SYSTEM CALLS (the waiter) ┌───────────────▼────────────────────────────┐ │ KERNEL SPACE (the kitchen — monolithic) │ │ ┌──────────────┬───────────────────────┐ │ │ │ Processes │ Memory │ │ │ │ fork, exec, │ virtual memory, │ │ │ │ scheduler │ paging, allocators │ │ │ ├──────────────┼───────────────────────┤ │ │ │ File system │ Network │ │ │ │ VFS → ext4, │ TCP/IP, sockets │ │ │ │ procfs, NFS │ │ │ │ ├──────────────┼───────────────────────┤ │ │ │ IPC │ Device drivers │ │ │ │ pipes, │ disk, keyboard, NIC │ │ │ │ signals │ (+ loadable modules) │ │ │ └──────────────┴───────────────────────┘ │ └───────────────┬────────────────────────────┘ │ ┌───────────────▼────────────────────────────┐ │ HARDWARE — CPU, RAM, disk, screen, etc. │ └────────────────────────────────────────────┘
✅ Six parts to name and explain (2 lines each)
  • Process management — creates and destroys processes (fork, exec, wait) and decides who runs next using the CFS scheduler (Completely Fair Scheduler = gives every process a fair share of CPU).
  • Memory management — gives each process its own virtual memory, moves pages between RAM and disk, and allocates space using the buddy system (big blocks) and slab allocator (small objects).
  • File system / VFS — one common interface so the same "open / read / write" commands work on ext4, NFS, USB drives, etc. In Linux, everything is a file — even devices and system information.
  • Network stack — the TCP/IP implementation and sockets used by browsers, servers, etc.
  • IPC — ways for processes to talk: pipes, signals, message queues, shared memory, sockets.
  • Device drivers + LKMs — small programs that know how to drive hardware; can be loaded or removed without rebooting.
⚑ Extra (not asked in 7 papers, but safe to know)
The boot chain: BIOS/UEFI → bootloader (GRUB) → kernel loads → systemd starts services. Also: namespaces + cgroups — the two Linux features that make Docker containers possible. Also SELinux / AppArmor for stronger security.

2. Memory management in Linux 10 MARKS

Exam asks: "Explain memory management in Linux with the help of a diagram" and short notes worth 5 marks twice.
🧠 In simple words — the library idea
Imagine your computer's RAM is a small library, and your program thinks it has a huge bookshelf of its own. That huge bookshelf is virtual memory — it is an illusion given to the program. The books are pages. The library only fetches a book from the storeroom (the disk) when you actually ask for it. That is demand paging. If the library is full, it puts an old book back in the storeroom to make space — that is page replacement / swapping. The librarian's catalogue that says "book X is on shelf Y" is the page table.
📝 Definition to write in the exam
Linux uses virtual memory with demand paging. Every process gets its own private, contiguous virtual address space, divided into fixed-size pages (usually 4 KB). These virtual pages are mapped to physical page frames in RAM through multi-level page tables. A page is loaded from disk only when it is first needed — a page fault signals the kernel to bring it in.
✅ Steps to write (this is the answer)
  • Address space — each process sees its own address space (code, data, heap, stack). It cannot see another process's memory.
  • Page tables + TLB — virtual address → physical address, translated by the page table; the TLB is a small fast cache of recent translations.
  • Demand paging — a page is read from disk only when touched. A page-fault handler checks the address is valid, finds a free frame, loads the page, updates the table, and reruns the instruction.
  • Getting free frames — the buddy allocator manages big blocks of pages (powers of two); the slab allocator carves pages into small same-sized pieces for kernel objects.
  • Swapping — when RAM is low, less-used pages go to a swap area on disk.
  • Overcommit and OOM killer — Linux may promise more memory than it has; if it runs out, the Out-Of-Memory killer kills a process to save the system.
⚑ Extra
Copy-on-write: when Linux forks a process, both share the same pages until one writes to them — then a copy is made. Page cache: file data is kept in RAM to speed up later reads. Check memory with free, vmstat, /proc/meminfo.

3. Security features in Linux 10 MARKS

Exam asks: "Discuss Linux security with respect to (i) User Accounts (ii) File Permissions (iii) Encrypted Storage (iv) Remote Access." The 10-mark question literally gives you the four headings — answer each separately. The 5-mark short note just needs all four named.
🧠 In simple words — a hotel
User accounts = the guest list at reception (who are you?). File permissions = the room key (which rooms can you open?). Encrypted storage = a safe (even if someone steals it, they cannot read the contents). Remote access = the secure intercom/front desk line (how you enter from outside, safely).
✅ The four headings — write one paragraph each
  • (i) User accounts — every user has a unique UID and belongs to groups (GID). UID 0 is root, the administrator with full power. /etc/passwd stores account details; /etc/shadow stores hashed passwords (only root can read it). Login uses PAM. Use sudo for admin work instead of staying logged in as root.
  • (ii) File permissions — three kinds of people: owner / group / others; three rights: read (4), write (2), execute (1). So rwxr-xr-- = 754. Commands: chmod, chown, chgrp, umask. Special bits: SUID (run with owner's rights — how passwd works), SGID, sticky bit (only the owner can delete from /tmp). ACLs gives finer control.
  • (iii) Encrypted storage — LUKS / dm-crypt encrypts a whole disk or partition; a passphrase unlocks the key. Data is unreadable if the disk is stolen. Also eCryptfs/fscrypt for individual folders, and encrypted swap. Downside: small speed cost, and losing the key means losing the data.
  • (iv) Remote access — SSH (port 22) gives encrypted remote login, replacing insecure Telnet. Use public-key authentication, disable root login, and add a firewall (iptables/nftables) and fail2ban. Files move with scp/sftp.
⚑ Extra
SELinux / AppArmor — mandatory access control: even root is restricted by rules. Very likely extension question.

Four answers cover everything asked about Windows.

1. Process management and scheduling 10 MARKS

Exam asks: "Explain the process management and process scheduling in Windows-10" and "Explain in detail the process management in Windows 10."
🧠 In simple words — a factory
A process is like a factory: the building, the land, the electricity and the storeroom. A thread is a worker inside the factory. A factory with no workers produces nothing. Several workers can work in the same factory and share its tools (memory and files). The scheduler is the supervisor who decides which worker gets the machine next and for how long.
📝 Definition to write in the exam
A process is an object that owns the resources needed to run a program — a private virtual address space, an executable image, a handle table, and a security token. It contains one or more threads. A thread is the unit the scheduler actually runs; it has its own stack and registers but shares the process's address space and handles.
✅ What to write
  • Process creation — CreateProcess() → the kernel builds a process object, a virtual address space and a first thread, then loads the EXE and its DLLs.
  • States — ready → running → waiting (blocked) → terminated.
  • Scheduling is preemptive and priority-based — every thread has a priority from 0 to 31. Priorities 0–15 are normal (changeable), 16–31 are real-time (fixed).
  • Priority classes — idle, low, below normal, normal, above normal, high, real-time. A thread also gets temporary boosts (e.g. you click the window, or an I/O finishes) so the system feels responsive. The boost slowly fades — this is the "feedback" idea.
  • Time quantum + round robin — a thread runs for a short slice of time; when it expires it goes to the back of its queue and the next runnable thread runs. This is called round robin with multilevel feedback queues.
  • Multiprocessor support — threads can run on different CPU cores; affinity can pin them to a core.
⚑ Extra
Fibers (user-mode threads), job objects (manage a group of processes), I/O completion ports, DLLs, the Win32 API, and the Windows service model.

2. Memory management in Windows 10 MARKS

Exam asks (two named halves): "(i) Virtual Memory Organization (ii) Demand Paging" — answer both halves separately.
🧠 In simple words — a desk with a drawer
Your desk = RAM (small but fast). A large filing cabinet = the disk (huge but slow). Windows gives every program a fake big desk called virtual memory. When the program asks for something not on the desk, Windows fetches it from the cabinet (page fault). If the desk is full, it moves an old paper into the cabinet to make room. The working set is simply the pile of papers currently on your desk.
📝 Definition to write in the exam
Windows gives each process a private, contiguous virtual address space backed by physical RAM and a paging file (PAGEFILE.SYS) on disk. Demand paging means a page is loaded into RAM only when it is first accessed; a page fault tells the memory manager to fetch it.
✅ Part (i) — Virtual memory organisation
  • Each process gets its own address space, so no process can corrupt another.
  • On 32-bit Windows: 2 GB for programs + 2 GB for the OS (or 3 GB + 1 GB with a special switch). On 64-bit: enormously more.
  • Space is divided into free, reserved and committed regions using VirtualAlloc()/VirtualFree().
  • Page tables map virtual pages to physical frames or to a copy in the paging file.
  • Benefits: isolation, more address space than RAM, memory-mapped files, sharing DLLs between processes.
✅ Part (ii) — Demand paging
  • Only the pages actually used are brought into RAM → less RAM wasted, faster start-up.
  • Referencing a missing page causes a page fault. The OS checks the address is legal, finds a free frame (evicting an old page if needed), reads the page from disk, updates the page table, and restarts the instruction.
  • Working set = pages currently in RAM for a process; the OS trims it when memory is tight.
  • Soft fault = page is in RAM but not mapped for this process (cheap). Hard fault = must read disk (slow).
  • DEP (Data Execution Prevention) marks pages non-executable as a security measure.
⚑ Extra
ASLR (randomising memory layout), PAE (32-bit Windows using more than 4 GB RAM), NUMA, large pages, and Windows 10's memory compression (compress pages in RAM instead of immediately writing to disk).

3. Interprocess communication (IPC) 5 MARKS

Exam asks: "What is Interprocess communication? Explain how it is performed in Windows-10."
🧠 In simple words
IPC is just how two programs talk to each other. Two ways: pass a note (messages — pipes, sockets, mailslots) or share a whiteboard (shared memory — memory-mapped files, fastest for big data). Windows also has special "system-only" ways like ALPC.
📝 Definition to write in the exam
Interprocess communication is the set of mechanisms that allow two processes to exchange data or synchronise their actions. Windows supports both message-passing and shared-memory IPC through kernel objects accessed by handles.
✅ Name 5–6 with one line each
  • Pipes — a byte stream between processes; named pipes also work across a network (client–server).
  • Mailslots — one-way short messages, broadcast style.
  • Memory-mapped files — two processes map the same file into their memory → fastest way to share large amounts of data.
  • COM (Component Object Model) — a standard way for software components to call each other, even on another machine (DCOM).
  • RPC / ALPC — call a function in another process as if it were local; ALPC is the fast local version used by Windows services.
  • Sockets (Winsock) — TCP/IP communication, usually across machines.
  • Clipboard, Windows messages/WM_COPYDATA, DDE — for GUI applications.
  • Synchronisation objects — mutex, semaphore, event, critical section — these coordinate rather than carry data.

4. File system + features of Windows 10 5 MARKS EACH

Exam asks: "File system management in Windows 10" (Jun 23) and "Features of Windows 10" (Dec 25).
🧠 In simple words — the filing cabinet
A file system is how the computer organises files on the disk: where each file is stored, how to find it, who is allowed to read it, and how to recover if the power fails. NTFS is Windows' filing system — a well-organised cabinet with an index (the MFT), a log book (journaling) and locks on drawers (permissions).
✅ File system — points to write
  • NTFS is the main Windows file system; older ones are FAT32 and exFAT (used on USB sticks).
  • MFT (Master File Table) — a database-like table; every file and folder has a record in it.
  • Journaling — changes are logged first, so the disk can recover after a crash.
  • Security — per-file/folder ACLs (access control lists); EFS encrypts files; BitLocker encrypts the whole drive.
  • Also supports compression, disk quotas, hard/symbolic links and large drives.
  • Allocation methods — contiguous (fast but wasteful) vs non-contiguous: FAT uses a linked list of blocks; NTFS uses extents and indexes for fast access.
✅ Features — write 6 bullets
  • UWP — one app can run on PC, tablet, phone and Xbox.
  • Start menu, Taskbar, Action Center, virtual desktops, Snap layouts.
  • Cortana voice assistant and Windows Hello face/fingerprint login.
  • Security — UAC, Windows Defender, BitLocker, Secure Boot + TPM.
  • Virtualisation — Hyper-V, WSL (run Linux inside Windows), containers.
  • Cloud — OneDrive sync, cloud clipboard; automatic Windows Update.

1. Evolution of iOS + features 10 MARKS

Exam asks: "Describe the evolution of iOS. Also discuss the features of iOS." This exact question appeared twice (Jun 23 and Dec 23).
🧠 In simple words
iOS started in 2007 as the operating system of the first iPhone. It had no App Store at first. Apple added the App Store in 2008, then copying/pasting, then multitasking, then iCloud, then a completely new look in iOS 7, and later things like face recognition, augmented reality and home-screen widgets. It grew from a simple phone OS into a full mobile platform.
📝 Definition to write in the exam
iOS is Apple's mobile operating system for iPhone and iPad. It is a Unix-like system built on the XNU kernel (a mix of the Mach microkernel and BSD). It evolved from "iPhone OS 1" in 2007 into today's iOS with an app sandbox, App Store, multitasking, cloud sync and strong security.

2. iOS layered architecture 10 MARKS — 3 TIMES IN A ROW

Exam asks: "With a block diagram, explain the iOS-layered architecture with essential functions of all the layers." Asked Jun 2024, Jun 2025, Dec 2025.
🧠 In simple words — a building with 4 floors
Think of iOS as a building. The top floor is what you see and touch — buttons, screens, gestures. The bottom floor (basement) is the machinery — electricity, water, the boiler. The middle floors turn the basement's raw services into something the top floor can use. If the top floor needs music, it asks the floor below; that floor asks the one below it, and so on. Each floor only talks to the floor directly under it.
📝 Definition to write in the exam
iOS is organised into four layers: Cocoa Touch, Media, Core Services and Core OS. Each layer provides services to the layer above it and hides its own complexity. This makes apps easier to build, more consistent and more secure.

✅ One "significance" line per layer
  • Cocoa Touch — everything the user touches: UI controls, gestures, push notifications, app life cycle.
  • Media — all graphics, animation, audio and video.
  • Core Services — data storage, networking, location, contacts — the non-visual services.
  • Core OS — the base: kernel, memory, processes, device drivers, network stack, security.
⚑ Extra
XNU = hybrid kernel: Mach handles processes, threads, IPC and virtual memory; BSD handles POSIX, sockets and file systems. GCD (Grand Central Dispatch) makes it easy to run work on multiple cores. iOS uses APFS with snapshots and encryption.

3. iOS directories and iCloud container 5 MARKS

Exam asks: "iOS directories and iCloud container of iOS" / "Some of the commonly used directories in iOS."
🧠 In simple words
Each app gets its own locked apartment (a sandbox). Inside that apartment there are different rooms: a bedroom for important documents (Documents), a cupboard for settings (Library/Preferences), a rubbish bin (tmp), and a storage box that gets emptied (Caches). Some rooms are backed up to iCloud; some are not. On top of that there is a shared cloud locker (the iCloud container) where the same app on your iPhone and iPad can keep data in sync.
📝 Definition to write in the exam
iOS uses a sandbox: every app lives in its own container directory and cannot read another app's files. Inside the container, standard subdirectories separate user documents, preferences, caches and temporary files. An iCloud container is a special ubiquity area whose contents are synchronised across the user's devices through iCloud.

✅ iCloud container — 3 lines

🤖 ANDROID

1. Layered architecture of Android 10 MARKS

Exam asks: "Discuss the layered architecture of Android OS with the help of a diagram." Also short notes on "Libraries and Application Framework Layers" and "Android Libraries."
🧠 In simple words — a mobile phone company
Android is built like a company with 5 departments, stacked from the boss down to the workers:
  • The Apps are the customers facing staff (what you see).
  • The Application Framework is the help desk giving apps ready-made services (notifications, windows, location).
  • The Libraries + runtime are the specialist teams (graphics, database, video, and the engine that runs apps).
  • The HAL is the translator who converts a generic request into a command for a specific camera or sensor.
  • The Linux kernel is the building itself — power, security, transport, and the doors to the hardware.
The translator (HAL) is the clever bit: an app asks for "a photo" and does not need to know which camera chip is installed.
📝 Definition to write in the exam
Android has a five-layer software stack: Applications, Application Framework, Libraries + Android Runtime, Hardware Abstraction Layer (HAL), and the Linux Kernel. Each layer uses the services of the layer below. The Linux kernel handles hardware, processes, memory, security and networking; the HAL lets the upper layers work with any hardware.
🖼️ Diagram to draw
┌──────────────────────────────────────────────────────────┐ │ 5. APPLICATIONS │ │ Home, Phone, Contacts, Browser, your apps │ ├──────────────────────────────────────────────────────────┤ │ 4. APPLICATION FRAMEWORK ← ready-made app services │ │ Activity Mgr · Window Mgr · Package Mgr · Resource Mgr │ │ Notification Mgr · View System · Location/Sensor/ │ │ Telephony Mgr · Content Providers (share data) │ ├──────────────────────────────────────────────────────────┤ │ 3. LIBRARIES + ANDROID RUNTIME (ART) │ │ Surface Mgr (screen) · Media Framework · SQLite (DB) │ │ OpenGL ES/Vulkan (3-D) · FreeType (fonts) · WebKit │ │ SSL · Bionic libc · ART/Dalvik VM + core libraries │ ├──────────────────────────────────────────────────────────┤ │ 2. HARDWARE ABSTRACTION LAYER (HAL) ← the translator │ │ Camera · GPS · Audio · Bluetooth · Wi-Fi · Sensors │ ├──────────────────────────────────────────────────────────┤ │ 1. LINUX KERNEL ← the foundation │ │ processes · memory · drivers · network · power · SELinux │ │ Binder IPC (fast internal messaging) │ ├──────────────────────────────────────────────────────────┤ │ HARDWARE — chip, screen, camera, radio, battery │ └──────────────────────────────────────────────────────────┘
✅ Libraries short note (just name and group them)
  • Graphics: Surface Manager, OpenGL ES / Vulkan, SGL, FreeType.
  • Media: Media Framework (audio/video recording and playback).
  • Data: SQLite (database), Bionic libc (C library).
  • Web & security: WebKit/Chromium, SSL.
  • Runtime: ART / Dalvik VM plus the core Android/Java libraries — this is what actually executes your app.
⚑ Extra
Dalvik used to translate app bytecode while running (JIT). ART compiles it ahead of time (AOT) so apps start faster. Binder is the fast IPC used by all Android system services. Zygote is a pre-started process that Android copies to launch new apps quickly.

2. Memory management in Android 10 MARKS

Exam asks: "Explain the memory management in Android operating system" and a 5-mark short note.
🧠 In simple words — a small shop with a bouncer
A phone has limited RAM. Android does not use a big disk swap like a PC (flash memory is slow to write). Instead it acts like a shop with a bouncer: it keeps the customer you are dealing with right now (the foreground app) at the counter, and when space runs out it throws out the people who are just hanging around (background and empty apps). The bouncer uses a priority list — the more important the app, the later it gets thrown out. That list is exactly the "five process types" question.
📝 Definition to write in the exam
Android uses Linux virtual memory and per-process address spaces, but instead of traditional swap it uses the Low Memory Killer (lmkd). Every process gets an importance score (oom_adj); when free memory falls below a threshold the kernel kills the least important processes first. Compressed RAM (zRAM) and KSM are used instead of disk swap.
✅ Points to write
  • Per-process heap — each app gets its own virtual address space and its own heap; the ART garbage collector frees unused objects automatically.
  • No traditional swap — flash storage is slow and wears out, so Android uses zRAM (compress pages in RAM) and KSM (merge identical pages).
  • Low Memory Killer — monitors free memory; kills processes with the worst (highest) oom_adj score, i.e. the least important ones.
  • Importance hierarchy — foreground → visible → service → background → empty. Killed from the bottom upwards.
  • Warnings to apps — onLowMemory() / onTrimMemory() let an app release caches before it is killed.
  • Sharing — framework code and resources are shared between processes (copy-on-write from Zygote) to save RAM.
  • Measuring — PSS (Proportional Set Size) counts shared pages fairly; check with dumpsys meminfo.

3. The five Android process types 10 MARKS

Exam asks: "Discuss the following processes in Android mobile operating system: Foreground, Visible, Service, Background, Empty." (Jun 2025)
🧠 In simple words — a cinema
Foreground = the person actually watching the film (you are using the app right now). Visible = someone in the row in front whose head you can still see (you can still see the app, but it is not active). Service = the projector operator — you cannot see them, but music/light keeps running. Background = people waiting in the lobby. Empty = an empty seat kept free in case someone comes back. If the cinema gets too full, it throws out the empty seats and lobby people first, and never the person watching the film.
📝 Definition to write in the exam
Android ranks every process by importance. The Low Memory Killer uses this ranking to decide which process to kill when RAM is low — least important first — so that the user's current experience is never interrupted.
TypeWhen it is in this stateKilled?
1. ForegroundYou are using its screen, or a service with a notification is running, or a broadcast receiver is executingLast resort only
2. VisibleIts screen is still on display (e.g. behind a dialog), though you cannot interact with itAlmost never
3. ServiceA started service with no visible UI — music, downloads, syncOnly if needed for the above
4. BackgroundIts activity is stopped and hidden; another app is on topEarly — first to go under pressure
5. EmptyNo active components at all; kept only in a cache for a faster restartFirst — no reason to keep it

Add one line: Android keeps background apps in an LRU (least recently used) list and kills from the bottom of this hierarchy upward.

4. File management and security in Android 10 MARKS

Exam asks: "Discuss the file management and security features in Android operating system."
🧠 In simple words — a gated apartment block
Each app is a separate apartment with its own key (a unique Linux user ID). It cannot enter any other apartment. Android's security is a stack of locks: the apartment door (sandbox), the guest list (permissions), the security guard (SELinux), the seal on the package (app signing), and the alarm system (verified boot and encryption).
📝 Definition to write in the exam
Android's security is based on a per-app sandbox: each application runs as a different Linux UID in its own process, with its own private data directory. Additional layers are the permissions model, SELinux mandatory access control, application signing, verified boot and device encryption.
✅ File management — write these
  • Linux-style file system: /system (the OS, read-only), /data (apps and user data), /sdcard (shared/external storage), /cache, /boot. Common file systems: ext4, F2FS.
  • Each app's private folder: /data/data/<package-name>/ with files/, cache/, databases/ (SQLite), shared_prefs/.
  • Apps share data through Content Providers with controlled URI permissions, not by reading each other's folders.
✅ Security — write 6–8 bullets
  • Sandbox + unique UID — apps are isolated; one cannot read another's memory or files.
  • Permissions — declared in AndroidManifest.xml; dangerous permissions (camera, contacts, location) must be granted by the user at runtime on Android 6+. Levels: normal, dangerous, signature.
  • SELinux — mandatory access control enforced since Android 5.0; restricts even privileged processes.
  • App signing — every APK is signed with a developer certificate to prove identity and integrity.
  • Verified Boot / dm-verity — checks at startup that the OS has not been tampered with.
  • Keystore — cryptographic keys stored in hardware-backed secure storage; non-exportable.
  • Encryption — full-disk (FDE) or modern file-based encryption (FBE) with Direct Boot.
  • Network — TLS by default; cleartext traffic restricted.
⚑ Extra
Android's four components — Activity, Service, Broadcast Receiver, Content Provider — and the Intent that connects them. Project Treble, ADB, Android version names, Play Protect.

⚡ Quick revision — one line per answer

  • Linux architecture — free, open-source, monolithic kernel; apps → system calls → kernel (processes, memory, VFS, network, IPC, drivers) → hardware.
